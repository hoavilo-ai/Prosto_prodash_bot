# Бот «Просто Продажник» — гайд по возражениям в один клик

Бот на `/start` проверяет, подписан ли человек на канал @prosto_prodash. Не подписан — просит подписаться и даёт кнопку «Я подписался». Подписан — сразу присылает питч + PDF-гайд «Обработка возражений» и кнопки на канал и запись на тренинг. Также уведомляет вас в личку о каждой успешной выдаче гайда.

## Шаг 1. Создать бота через @BotFather (2 минуты)

1. Откройте Telegram, найдите **@BotFather**, нажмите Start.
2. Отправьте команду `/newbot`.
3. Придумайте имя бота (например, «Просто Продажник — гайд по возражениям»).
4. Придумайте username бота — обязательно заканчивается на `bot` (например, `prosto_prodash_bot`).
5. BotFather пришлёт **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`. Скопируйте и сохраните его — он понадобится на шаге 3.

## Шаг 1.5. Добавить бота админом в канал (обязательно для проверки подписки)

Без этого шага бот технически не может узнать, подписан человек на канал или нет — Telegram API так устроен: проверять подписку могут только админы канала.

1. Откройте канал **@prosto_prodash** → Управление каналом → Администраторы → Добавить администратора.
2. Найдите username вашего бота (тот, что вы придумали на шаге 1) и добавьте его. Особые права не нужны — достаточно самого факта, что бот в списке админов.

Если пропустить этот шаг, бот не сломается — гайд по-прежнему будет отправляться (чтобы не блокировать всех подряд из-за конфигурации), но проверка подписки работать не будет и по факту не будет ничего фильтровать.

## Шаг 2. Завести аккаунт на Railway

1. Зайдите на [railway.app](https://railway.app) и зарегистрируйтесь (можно через GitHub-аккаунт — если его нет, создайте бесплатно на [github.com](https://github.com), это тоже 2 минуты).
2. Railway даёт бесплатный пробный лимит — этого достаточно для одного лёгкого бота.

## Шаг 3. Выложить код бота

Самый простой путь — через GitHub:

1. На [github.com](https://github.com) нажмите **New repository**, назовите его, например, `prosto-prodash-bot`, сделайте его **Private**, нажмите Create.
2. На странице репозитория нажмите **Add file → Upload files** и загрузите туда файлы из этой папки: `bot.py`, `requirements.txt`, `Procfile`, `lead_magnet.pdf`. Нажмите Commit changes.

   (Файл `env.example.txt` загружать не обязательно — это просто памятка, какие переменные окружения существуют и как они называются. Сами переменные вы задаёте в Railway на шаге 4-5, а не через этот файл.)
3. Вернитесь в Railway → **New Project → Deploy from GitHub repo** → выберите репозиторий `prosto-prodash-bot`.
4. Railway сам определит, что это Python-проект (по `requirements.txt`), и начнёт сборку.

## Шаг 4. Указать токен бота

1. В Railway откройте ваш проект → вкладка **Variables**.
2. Добавьте переменную:
   - `TELEGRAM_BOT_TOKEN` = токен, который вы скопировали от BotFather на шаге 1.
3. Сохраните — Railway автоматически перезапустит бота с этой переменной.

Через минуту бот должен ожить: найдите его в Telegram по username и отправьте `/start`. Если вы уже подписаны на канал — придут питч и PDF-гайд с кнопками. Если нет — придёт приглашение подписаться с кнопкой «Я подписался».

Если username вашего канала для проверки подписки отличается от `@prosto_prodash`, добавьте в Railway ещё одну переменную:
   - `CHANNEL_USERNAME` = `@ваш_username_канала`

## Шаг 5. Настроить уведомления о новых подписчиках (необязательно, но полезно)

1. Напишите вашему боту команду `/myid` — он пришлёт ваш `chat_id`.
2. В Railway → **Variables** добавьте:
   - `ADMIN_CHAT_ID` = число, которое прислал бот.
3. Сохраните — после перезапуска бот будет присылать вам сообщение о каждом новом человеке, нажавшем `/start`.

## Шаг 6. Узнать, сколько раз скачали гайд

Бот сам считает каждую отправку файла (в том числе если один и тот же человек нажал `/start` несколько раз — это «сколько раз скачали», а не «сколько разных людей»).

Посмотреть счётчик можно двумя способами:
- Написать боту `/stats` (сработает, только если задан `ADMIN_CHAT_ID` из шага 5, и писать нужно именно с того аккаунта) — придёт сообщение вида «Гайд выдан: 7 раз(а)».
- Читать итог в конце каждого уведомления о новом подписчике — там теперь есть строка «Всего выдач гайда: N».

**Важно про надёжность счётчика.** По умолчанию число хранится в файле рядом с ботом на Railway — это переживёт обычные перезапуски, но **обнулится**, если вы в следующий раз обновите код через GitHub (передеплой создаёт новый контейнер с чистого листа). Чтобы счётчик не терялся:

1. В Railway откройте ваш сервис → вкладка **Settings** → раздел **Volumes** → **Add Volume**.
2. В поле **Mount path** укажите `/data` и сохраните (бесплатного лимита в 0,5 ГБ на пробном тарифе хватит с огромным запасом — счётчик занимает несколько байт).
3. Во вкладке **Variables** добавьте переменную `STATS_PATH` = `/data/stats.json`.
4. Сохраните — Railway передеплоит сервис. Теперь файл со счётчиком лежит на подключённом диске и переживёт любые будущие обновления кода.

Если пропустить этот шаг — ничего не сломается, бот продолжит считать, просто число обнулится при следующем обновлении кода на GitHub.

## Что дальше

- Ссылку на бота (`t.me/ваш_username_бота`) используйте как основной CTA везде, где раньше давали файл напрямую — в комментариях, личных сообщениях, подписи, при знакомстве на мероприятиях.
- Кнопки в боте ведут на `https://t.me/prosto_prodash` (канал) и `https://t.me/prosto_prodash_pr` (запись на тренинг) — если эти адреса нужно изменить, добавьте в Railway переменные `CHANNEL_URL` и/или `TRAINING_CONTACT_URL` с новыми ссылками.
- Если захотите обновить сам PDF-гайд — замените файл `lead_magnet.pdf` в GitHub-репозитории (Add file → Upload files, с тем же именем) — Railway пересоберёт бота автоматически.

## Если что-то не заработало

- Бот не отвечает: проверьте в Railway вкладку **Deployments → View Logs** — там будет видна ошибка. Самая частая причина — опечатка в токене.
- Нет уведомлений: убедитесь, что `ADMIN_CHAT_ID` — это именно число из `/myid`, без лишних символов, и что вы написали боту `/start` хотя бы раз после того, как задали эту переменную.
- Гайд выдаётся всем подряд, даже неподписанным: значит, бот не добавлен админом в канал (см. Шаг 1.5) — без этого проверка подписки не может работать технически, и бот намеренно пропускает всех, а не блокирует.
- Бот пишет «не вижу подписку» тому, кто точно подписался: Telegram иногда обновляет статус подписки с задержкой в несколько секунд — попросите нажать кнопку «Я подписался» ещё раз.

## Локальная проверка (для тех, кто хочет протестировать у себя перед деплоем)

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN=ваш_токен
python bot.py
```
